# AI-DLC Studio — Implementation Architecture (v1)

Status: binding for implementation. Derived from `docs/AI-DLC-Studio-PRD.md` and the code research in
`docs/research/` (read `00-index.md` first, then the doc for your module). Where this document and the
PRD's wording disagree, the **Decision log (§13)** explains why; the PRD's invariants (§6) always win.

Target runtime: the KiroCrew gateway that actually runs on the dev machine is the desktop bundle
`0.5.0-insider.9` (see `docs/research/01-kirocrew-app-runtime.md` §0). The source checkout at
`~/warren_ws/kirocrew` is 0.3.0 and is reference only. Studio nevertheless declares
`minKiroCrewVersion: "0.3.0"` and runs on both (see §4.0 and decision A10).

## 3. Authority model and lanes (PRD §6)

| Concern | Authority | Studio's role |
|---|---|---|
| Lifecycle, gates, questions, artifacts, audit, cursor | AI-DLC engine on disk | read; never write those files |
| Sessions, turns, human vs machine provenance, Slack | KiroCrew | observe (in-process `request.app["state"]`, feature-detected); submit only through the host's human lane |
| Registry, projections, actions, leases, receipts, preferences, archives, estimates, activity | Studio | own, in SQLite under `ctx.data_dir` |

### 3.1 Human-submission lane (the only way a decision reaches AI-DLC)

A human decision is a real user prompt to the intent's canonical KiroCrew slot (project = repo root,
agent = `aidlc`). kiro-cli fires `userPromptSubmit` → the AI-DLC adapter appends `HUMAN_TURN` and stamps
`aidlc/.aidlc-human-turn` → the conductor interprets the text → the engine commits (`GATE_APPROVED` + `[?]→[x]`,
or `GATE_REJECTED` + `[?]→[R]`). Research: `02-…` §2/§5/§9 + addendum, `05-…` §5–6 + addendum.

Submission is **two-phase**: Studio's backend owns the durable record and the preconditions, the human's own
browser session performs the send through the host's public chat API. The backend never calls a private host
function, so a gateway upgrade cannot silently break the only path a decision can take (the two gateway
generations already differ — see §7.0).

1. `POST /actions/{action_id}/submit` `{captured: {state_hash, boundary_token, question_digest?, stage_attempt},
   decision: {kind, feedback?, answers?}, confirmed_wire_text}`.
   Backend, in order:
   a. owner check (`request["app"] == ""` and the owner/local-bootstrap subject) — app tokens are refused;
   b. the action must be `Draft|Queued|NotDelivered`;
   c. compare-and-submit: re-read the live snapshot; if `state_hash`, `boundary_token`, `question_digest`,
      `stage_attempt` or the required evidence differ, or the snapshot is unstable, refuse `409 action_stale`
      and return the refreshed card;
   d. `confirmed_wire_text` must equal the server's own computed wire text byte-for-byte — a client cannot
      choose what gets sent;
   e. blocking consistency findings → `409 state_inconsistent`; open breaker → `409 circuit_open`;
   f. `ExecutionLease(resolved_identity)` acquired, or `409 repo_busy {owner}`;
   g. host preflight through `HostBridge` (read-only): the bound slot exists, `slot.project == canonical_path`,
      `slot.agent == "aidlc"`, and every busy predicate is clear (`running`, `_in_stage_execution`,
      `_stop_state != "idle"`, `queue_depth`, undone approval futures, running/queued subagents) →
      else `409 session_busy`;
   h. record the pre-dispatch human-presence baseline (`HUMAN_TURN` count and audit tail digest);
   i. CAS `→ Delivering` with `delivery_id`, `payload_digest`, `wire_text`, `slot_key`, `session_key`,
      `lease_generation`, `deadline_at = now + DELIVERY_ACK_DEADLINE_SECS` — durably committed (SQLite
      `synchronous=FULL`) **before** returning, therefore before the host is called (PRD §11.5);
   j. return `{action_id, status: "Delivering", delivery_id, slot_key, wire_text, expires_at, lease_generation}`.
2. UI: `POST /api/chat?ws=1` `{message: wire_text, slot: slot_key}` with the user's own dashboard cookie.
   Receipt `{ok:true, slot, mid?}` = enqueued and running; `{ok:true, queued:true}` = enqueued behind a turn;
   `{ok:true, steered:true}` is never requested (Studio never sets `steer`). A 4xx/409 body is authoritative
   proof it was never enqueued.
3. UI: `POST /actions/{action_id}/delivery` `{delivery_id, outcome: "delivered"|"not_delivered"|"uncertain",
   http_status, receipt}` → CAS `Delivering → Delivered | NotDelivered | DeliveryUncertain`; `not_delivered`
   is accepted only with an authoritative 4xx/409 receipt. `Delivered → Processing` immediately.
4. If step 3 never arrives by `deadline_at` (90 s), the reconciler moves the action to `DeliveryUncertain` and
   then tries to prove delivery from evidence: a `user` row whose content equals `wire_text` (or whose `meta.mid`
   equals the receipt's `mid`) at or after `delivering_at` in the canonical slot transcript → `Delivered/Processing`;
   nothing found and the slot never became busy → `NotDelivered` (re-queueable); anything ambiguous stays
   `ReconciliationRequired` for a human.
5. The reconciler (§7) then waits for the action's declared resolution evidence (`StateChanged`), or a completed
   turn plus a superseded boundary where the contract expects no transition (`ResolvedNoTransition`), or a
   deadline/session replacement (`DeliveryUncertain → ReconciliationRequired`). It asserts the human-presence
   invariant: a human dispatch must add exactly one `HUMAN_TURN`; a machine dispatch must add none (v1 has no
   machine dispatch, so any movement without a human action opens the deterministic security breaker, FR-SES-010).

Because the host itself appends the `user` row and starts the turn, Studio writes nothing into the session and
needs no private host symbol on this path. `permissions.api` therefore includes `/api/chat` (the prefix covers
`/api/chat/slots*`), which the UI also uses to create the canonical slot, bind its project, read the transcript
for the Conversation tab, and force-stop a turn. If the host chat API is unreachable the UI reports it and the
action stays `Queued`; nothing is half-sent.

Wire text is a Studio protocol constant, case-sensitive, shown verbatim in the confirmation before sending
(FR-GATE-002; the engine supplies no response token — `present-gate` is an unemitted placeholder):

| Decision | Wire text |
|---|---|
| Gate approve | `Approve` |
| Gate request changes | `Request Changes: <feedback>` |
| Gate accept as-is (only from the 4th attempt, i.e. after three rejections) | `Accept as-is` |
| Plan-approval checkpoint approve / reject | `Approve Plan` / `Request Changes: <feedback>` |
| Summary-confirmation checkpoint | `Looks correct` / `Request changes: <feedback>` |
| Question group | Exact option labels from a supported stable file, multi-select and Other text, one atomic submit. Multiple questions use `Q<n>` lines plus the v2 one-audit-receipt instruction. Native blocking waits route to the canonical conversation. |
| Run to next checkpoint | `/aidlc` |
| Resume a parked intent | `/aidlc --resume` |
| Ask AI to prepare commit | `Please prepare a commit for the current AI-DLC changes. Do not push.` |

`docs/design/wire-text.json` is the pinned source these strings are checked against, in both the backend
(`constants.WIRE_TEXT`) and the UI (`ui/src/lib/wire.ts`). Picking the active intent is **not** a wire text: it is
the admin-lane cursor switch (§3.3), because sending `/aidlc intent <name>` as a prompt would mint a human turn.

Casing is load-bearing: the gate label is `Request Changes` while the summary-confirmation label is
`Request changes` (`05-…` addendum A7/A8, `06-…` addendum). Both live in `constants.WIRE_TEXT` with a test that
pins every string.

Slack in v1 is **notification plus deep link only**. KiroCrew owns Slack callbacks and an app cannot register its
own `action_id` (`02-…` §7.2); the one seam that looked usable — posting an `[OPTIONS: …]` block on a thread linked
to the canonical slot — was rejected in review because the host re-dispatches *whatever option the user picks* as a
user turn on the `aidlc` slot. Every option is therefore wire text, so a second option such as "Open in Studio"
would be typed straight into the AI-DLC conversation, and a stale card could resolve a boundary the user is no
longer looking at with no compare-and-submit in between. Studio posts the decision summary and a deep link
(`/apps/aidlc-studio?view=actions&action=<id>`), and the decision is made in Studio where the evidence and the
staleness check are. Notification `url`s must be dashboard-internal paths (the host validates that).
`slack_quick_action_eligible()` therefore always returns `(False, "host_seam_unavailable")` and Settings shows the
capability as unavailable with that reason (PRD FR-SLK-004 is met by refusing rather than by faking eligibility).
`POST /slack/actions/callback` exists as an owner-authenticated correlation endpoint that records a hint and
authorizes nothing.

### 3.2 Machine lane — disabled by construction (S12 fails on Kiro)

Every KiroCrew path that reaches kiro-cli is `session/prompt` and fires `userPromptSubmit`
(`02-…` §5); `_session/steer` is unproven and needs a live turn. Therefore `Keep moving`, night window,
stable-boundary auto-failover and any unattended continuation are **absent** in v1: settings show them as
`Unavailable — S12 unproven` with the reason; `/keep-moving` returns `409 machine_lane_unavailable`; Run
performs exactly one human-initiated turn (FR-RUN-001 second sentence). `MachineActionBroker` exists as a
module that always refuses and records a Studio Activity row, so the security breaker (FR-SES-010) has a home.

### 3.3 Admin lane — engine-owned utility verbs, no model turn

Under `RepoAdminLease`, Studio runs allowlisted AI-DLC CLI verbs with `bun` in the repo, `--project-dir <repo>`,
scrubbed env (§10). Allowed: `aidlc-utility.ts version|status|intent --json|space --json|intent <dirName>|
space <slug>|intent-create …|recompose …|scope-change …|config-change …|config-list --json`, `aidlc-state.ts get|lookup|resume|count`,
`aidlc-utility.ts doctor` (labelled "read-only for state; appends HEALTH_CHECKED/GUARDRAIL_LOADED audit rows",
only on explicit user request). Never: `aidlc-orchestrate.ts next|report|park`, `aidlc-state.ts approve|
reject|revise|advance|…`, `aidlc-audit.ts append*`, `aidlc-jump.ts execute`, repair verbs.
Cursor switch = `intent <dirName>` then read-back, and it runs before **every** dispatch, not just Run (`aidlc/active-space`, `.../active-intent`, dir has
`aidlc-state.md`, `intent --json`.active, sha256(state)); any mismatch refuses dispatch (FR-SES-006).

## 4. Storage (`storage.py`) — SQLite, crash-safe CAS

### 4.0 Module namespace bootstrap (works on every gateway version)

`module_loader` loads `backend/routes.py` by file path as `_kirocrew_app_aidlc-studio.backend.routes` and never
touches `sys.path`. Only the 0.5.0 loader pre-registers the parent packages, so `backend/routes.py` and
`backend/hooks.py` each begin by registering Studio's **own** namespace package before importing anything:

```python
import importlib, importlib.machinery, importlib.util, sys
from pathlib import Path

_BACKEND_DIR = Path(__file__).resolve().parent          # <app>/backend
_NS = "_aidlc_studio_backend"                            # private, dot-free app slug -> no collisions

def _bootstrap():
    if _NS not in sys.modules:
        pkg = importlib.util.module_from_spec(importlib.machinery.ModuleSpec(_NS, None, is_package=True))
        pkg.__path__ = [str(_BACKEND_DIR)]
        sys.modules[_NS] = pkg
    return importlib.import_module(f"{_NS}.studio")

studio = _bootstrap()   # from here on `studio.*` and normal relative imports inside studio/ work
```

Inside `backend/studio/**` only **relative** imports are used (`from . import constants`,
`from .storage import Storage`). Consequences: identical behaviour on 0.3.0 and 0.5.0, tests can import the same
way, and `unload_app_modules` on disable drops the host's `_kirocrew_app_*` keys while `_aidlc_studio_backend`
is cleaned up by `on_shutdown` (which deletes its own `sys.modules` entries) so a re-enable re-reads the files.

`ctx.storage` (JSON kv, atomic replace, no fsync, no locking) is used only for the migrated legacy repo list
read. Everything Studio owns lives in `ctx.data_dir / "studio.sqlite3"` (`PRAGMA journal_mode=WAL`,
`synchronous=FULL`, `busy_timeout=5000`, `foreign_keys=ON`). All DB work runs in `asyncio.to_thread`
(the gateway has a loop-stall watchdog that kills the process after ~25 s of blocked loop).

Tables (columns mirror PRD §14; `*_json` = JSON text):

- `repos(id TEXT PK, resolved_identity TEXT UNIQUE, canonical_path, git_common_dir_identity, label, added_at,
  last_seen, platform, install_status, installed_engine_version, receipt_version, archived INT, availability,
  availability_detail, legacy_console_id)`
- `intent_bindings(repo_id, resolved_repo_identity, space, intent_uuid, intent_dir, intent_slug,
  canonical_session_key, binding_generation INT, keep_moving INT, archive_state, last_stable_boundary_json,
  PRIMARY KEY(repo_id, space, intent_dir))`
- `actions(action_id PK, type, risk_class, repo_id, resolved_repo_identity, intent_uuid, intent_dir, space,
  stage, unit, captured_state_hash, boundary_token, question_digest, payload_digest, human_text,
  wire_text, status, status_generation INT, session_key, lease_generation INT, created_at, updated_at,
  delivering_at, delivered_at, resolved_at, deadline_at, evidence_json, retry_fingerprint, source,
  dedupe_key UNIQUE)` — `dedupe_key` = `type:repo:intent:stage:boundary_token` so one live card per boundary.
- `action_transitions(id INTEGER PK, action_id, from_status, to_status, generation, at, reason, evidence_json)`
- `execution_leases(resolved_repo_identity PK, intent_uuid, session_key, action_id, acquired_at, heartbeat_at,
  generation INT, observed_busy_state)`
- `admin_leases(resolved_repo_identity PK, operation_type, transaction_id, acquired_at, heartbeat_at, generation INT)`
- `install_transactions(transaction_id PK, repo_id, resolved_repo_identity, kind, status, studio_version,
  engine_version, payload_digest, started_at, finished_at, staging_dir, backup_dir, prior_receipt_id, steps_json, error)`
- `install_receipts(receipt_id PK, repo_id, resolved_repo_identity, studio_version, engine_version, payload_digest,
  committed_at, prior_receipt_id, files_json, status)` — `files_json` = `[{path, ownership, sha256|canonical_digest, kind:"file"|"fragment", fragment_key?}]`
- `preferences(key PK, value_json, updated_at)`
- `activity(id INTEGER PK, at, source ('studio'|'aidlc'|'kirocrew'|'git'), kind, severity, repo_id, intent_dir,
  stage, action_id, session_key, message, evidence_json, redacted INT)` — Studio-originated rows only; AI-DLC audit

- `events(seq INTEGER PK AUTOINCREMENT, at, type, payload_json)` — SSE backing log (ring-trimmed at 10 000).
- `calibration(id INTEGER PK, scope, depth, stage_class, model_class, review_iterations, test_secs, est_json,

## 5. Read model

### 5.1 RepoRegistry
- `resolve_identity(path) -> ResolvedIdentity{canonical_path, st_dev, st_ino, git_common_dir, identity_str}`;
  `identity_str = f"{dev}:{ino}"` when available else `sha256(realpath + '\0' + git_common_dir)`.
- `add(path, label)`: preflight (read-only), refuse duplicates (`409 duplicate_identity`), refuse sensitive paths
  (`kiro_crew.security.is_sensitive_path`), refuse non-directories/relative paths.
- `remove(repo_id)`: unregister only. `rebind(repo_id, new_path)`: only when the old identity is unavailable.
- Availability states: `available | moved | permission_denied | unavailable | identity_unprovable`.
- Health: install status from `AidlcReader.detect_install(repo)` (`not_installed | installed | drift | recovery_required`)
  + engine version from `.kiro/tools/aidlc-version.ts` (regex `AIDLC_VERSION = "(.+?)"`) + receipt status.
  Two versions are reported, not one: `engine_version` for the harness Studio **reads** (`.kiro`, else the first harness
  present — a `.claude` repository reports `.claude`) and `own_engine_version` for the harness Studio **manages**
  (`STUDIO_HARNESS_DIR`, null when `.kiro` is absent). Only the install lane keys on the second (A26).

### 5.2 AidlcReader (parsers) — see `04-aidlc-on-disk-model.md`, `05-…` §2
Files read (all relative to repo, containment-checked, size-capped, never followed outside the repo):
`aidlc/active-space`, `aidlc/spaces/<s>/intents/{intents.json,active-intent}`, `<record>/aidlc-state.md`,
`<record>/.aidlc-active-directive.json`, `<record>/.aidlc-recovery.md`, `<record>/.aidlc-goal-stop`,
`<record>/audit/*.md`, `<record>/<phase>/<stage>/**` (artifacts, `<stage>-questions.md`, `memory.md`, review files),
`<record>/construction/<unit>/<stage>/**`, `.kiro/tools/data/{stage-graph,scope-grid,harness}.json`,
`.kiro/scopes/aidlc-*.md`, `.kiro/aidlc-common/stages/<phase>/<slug>.md` (frontmatter), `.kiro/tools/aidlc-version.ts`,
`aidlc/.aidlc-turn-counter`, `aidlc/.aidlc-human-turn`, `aidlc/.aidlc-sessions/*`, `aidlc/.aidlc-compose-pending`,
`<record>/.aidlc-hooks-health/*`, `<record>/.aidlc-stop-hook/block-count.json`, `<record>/.aidlc-plan.json`,
`<record>/verification/**`, `<record>/runtime-graph.json`.
Grammar: checkbox line `^- \[([ xXsSrR?-])\] (\S+)(?:\s*(?:—|–|--)\s*(.*))?$`; field line `^- \*\*(.+?)\*\*:\s*(.*)$`;
audit block split on `\n---\n`, fields `**Key**: value`, `**Event**: TYPE`. State Version 7 and 8, 32 and 33
stage graphs must both parse (fixtures from payload v2.3.0 and the real DevDelta 2.6.2 install).
Stable read-verify: `stable_read(path) -> Snapshot{bytes, size, mtime_ns, sha256}` reads twice; if size/mtime differ
the snapshot is `unstable=True` and the card renders `Refreshing` (FR-ACT-009).
`boundary_token = sha256(state_sha256 + ':' + last_gate_or_question_event_ts + ':' + current_stage + ':' + revision_count)`.
`question_digest = sha256(bytes of <stage>-questions.md)` when present.

### 5.3 ConsistencyEngine (§12.3 invariant set)
Findings `{code, severity: 'blocking'|'warn'|'info', message, evidence[]}`. Codes: `dangling_cursor`,
`intent_registry_missing_row`, `directive_state_digest_mismatch`, `phase_stage_disagreement`,
`completed_count_mismatch`, `total_count_mismatch`, `stage_graph_drift`, `gate_without_audit_row`,
`audit_gate_without_checkbox`, `missing_required_artifact`, `state_version_unsupported`, `receipt_drift`,
`install_recovery_required`, `duplicate_identity`, `delivery_uncertain_action`, `lease_conflict`. Any `blocking`
finding blocks Run/Submit (`409 state_inconsistent`).

### 5.4 Projection
- Intent operational state (PRD §11.2) derived: disk `Status: Completed` → `Completed`; `Parked` → `Parked`;
  any `[?]`/`[R]`/pending question → `WaitingForYou`; slot running → `Running`; queued action/lease → `Queued`;
  breaker → `CircuitOpen`; RetryEligible/Failed from the last failed action; Interrupted from a force-stop marker;
  ReconciliationRequired from blocking findings or uncertain actions; archived flag → `Archived`; else `Idle`/`Paused`.
- Action derivation (one card per live boundary, `dedupe_key`): `gate` (`[?]` row), `revision` (`[R]` shown as
  informational), `question` (blank `[Answer]:` in the current stage's questions file or a `question_card`/
  `[OPTIONS:]` on the canonical slot), `missing_input` (intent-pick ask / missing scope), `recovery`
  (blocking findings, Interrupted, mid-stage session loss), `delivery_uncertain`, `failure` (ERROR_LOGGED burst,
  turn error rows, timeout), `circuit_breaker`, `install_conflict`, `budget_stop` (turn cap reached). Priority order
  and oldest-first per FR-ACT-003/004.
- Map: stage-graph ∪ state rows → five phases; per stage `{slug, phase, state, mode, agent, review_class, gate,
  per_unit, consumes, produces, depends_on, elapsed, artifacts[], skipped_reason}`; units from `construction/<unit>/`.
- Artifacts: enumerate regular files under the record dir (≤1 MiB each rendered, ≤2 000 files), metadata
  `{artifact_id (sha1 of relpath), relpath, stage, unit, size, mtime, sha256, kind}`; content served with
  `text/markdown; charset=utf-8` and rendered client-side by the host's sanitising `MarkdownRenderer`.

## 6. HumanActionBroker + RepoScheduler (`actions.py`, `leases.py`)

Action state enum (exact PRD §11.1 strings): `Draft Queued Delivering Delivered Processing StateChanged
ResolvedNoTransition NotDelivered DeliveryUncertain ReconciliationRequired Failed Cancelled`. Transition table is
data (`ALLOWED_TRANSITIONS`) and every transition writes `action_transitions` + an `events` row.

Resolution contracts per action type (what `Processing → StateChanged/ResolvedNoTransition` requires):

| type / decision | evidence |
|---|---|
| gate / Approve | new `GATE_APPROVED` block for the stage AND row `[?]→[x]` (or Current Stage moved) |
| gate / Request changes | new `GATE_REJECTED`+`STAGE_REVISING` AND row `[?]→[R]` |
| question | question file digest changed with no blank `[Answer]:` for that group OR `QUESTION_ANSWERED` row, AND host turn completed → `ResolvedNoTransition` |
| run / resume | host turn started and ended; `StateChanged` if any stage row/Current Stage changed, else `ResolvedNoTransition` |
| force-stop | host `/stop` receipt + slot not running → `ResolvedNoTransition`, intent marked Interrupted |

Deadlines: `PROCESSING_DEADLINE = min(agent.chat_turn_timeout_secs, 7200)` from `delivered_at`; session termination or
replacement before evidence → `DeliveryUncertain`. Cancellation legal only in `Draft/Queued`, after `NotDelivered`,
or with host-confirmed cancel before execution.

Leases: `ExecutionLease` acquired at `submit`, heartbeat every 15 s by the reconciler while the slot is running,
released at resolution; `RepoAdminLease` for install/upgrade/recovery/intent-create/recompose/cursor switch; the two
are mutually exclusive per `resolved_repo_identity`; admin waits (`409 repo_busy` with `retry_after`) and never
preempts; reclaim requires `slot.running == False` and no host busy state AND boundary reconciliation, except where the
lease is provably the debris of a crashed holder (nothing was dispatched, or the settled action still carries this
lease's own generation), which waives the boundary because demanding one there deadlocks the repository — time alone
never reclaims (`FR-SES-007`). Global concurrency cap from preferences applies across repos.

Circuit breaker (§11.4): key `intent:fingerprint`; transient fingerprints (`transport|rate_limit|acp_timeout`) open at 3;
deterministic (`validation|permission|dependency|guard|human_marker_movement|config`) open immediately; opening
creates one `circuit_breaker` action and one notification; `Retry now` resets.

## 10. Security rules (enforced in code and tests)

- Path containment: every user-supplied path or id is resolved and checked `is_relative_to(repo_root)` after
  `realpath`; symlinks that escape are refused; only regular files are read; `is_sensitive_path` refusals.
- Bounded reads: state ≤512 KiB, JSON ≤4 MiB, artifact ≤1 MiB rendered, audit tail-read ≤256 KiB per shard,
  ≤2 000 artifacts per intent, per-repo scan deadline 10 s, all in `to_thread`.
- Subprocesses (`engine.py`, `git_observer.py`): argv lists only (never shell), `cwd=repo`, timeout ≤60 s,
  env = minimal (`PATH`, `HOME`, `LANG`) with every `AIDLC_*`, `CLAUDE_*`, `AWS_AIDLC_*` key stripped and
  `AIDLC_SKIP_HUMAN_PRESENCE_GUARD`/`AIDLC_SKIP_ARTIFACT_GUARD` explicitly asserted absent; git argv checked
  against `GIT_WRITE_VERBS` deny set (`add commit push pull merge rebase checkout switch reset restore stash tag
  branch cherry-pick revert am apply clean rm mv fetch remote submodule`) and a static test greps the backend.
- Auth: every route requires `request.get("user")`; every mutation additionally requires the dashboard owner
  (`request.get("app","") == ""` and owner id match / local bootstrap subject). App tokens are refused on mutations.
- Redaction: `kiro_crew.security.redact_credentials` on every string leaving the backend in errors/activity/export;
  exports omit human_text by default; repo paths appear only for the registered repo itself.
- Frontend: no `dangerouslySetInnerHTML`; markdown only via the host `MarkdownRenderer` (allowlist sanitiser,
  mermaid strict); links with active schemes are not rendered as links; deep links carry ids only.

## 11. API surface

All routes are relative and the host mounts them under `/api/apps/aidlc-studio`. The **authoritative,
ordered route table is `docs/design/contracts.md` §2.10**, with the request and response shape of each
route in §2.1–§2.9 and the `ActionCard` JSON in §2.11; `handlers/common.all_routes()` must produce exactly
that list, and `tests/test_handlers_auth.py` pins it. This section only states the rules that hold for all
of them:

- Every route requires an authenticated user; every `POST`/`PUT`/`DELETE` additionally requires the
  dashboard owner and refuses an app token, while reads accept either.
- Registration order matters twice, because the host tries parameterised routes in order:
  `/repos/preflight` before `/repos/{repo_id}`, and `/repos/{repo_id}/intents/plan/preview` before
  `/repos/{repo_id}/intents/{intent}`.
- No route may be named `config`, `manifest`, `enable`, `disable`, `update`, `uninstall`, `open`, `dev`,
  `token` or `migrate-cleanup`: the host's own app-management handlers claim those paths.
- Every non-2xx body is `{"error", "code", "details"}` with the code drawn from `errors.ERROR_CODES`, and
  the status comes from that table rather than from the handler.
- Every mutation returns the Studio action or transaction id plus a status endpoint or event stream to
  watch. **A 2xx never means AI-DLC changed** — only the reconciler's observed evidence does.
- `{intent}` in a path is an `intent_key` (`intent_dir`, or `space~intent_dir` outside the default space).
