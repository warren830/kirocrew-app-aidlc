# Plan 预览勾选后无法取消 · 2026-09-11

根因在预览锁定规则。阶段原本被预设排除时可选，手动选中后却被额外追加 ALWAYS 锁。
另一个叠加问题是，新增可选阶段补足了预设本来就允许的依赖缺口后，被误锁为不可移除的生产者。
这与后端依赖校验仅拒绝“新引入的缺口”的规则不一致，形成只能选、不能撤销的操作。

现在 ALWAYS 约束按预设或已提交状态的基线判断；预览中新增的可选阶段可以撤销。
展示依赖锁时忽略预设已有的允许缺口，新加入消费者的真正必需输入仍会锁定。
已完成阶段、当前阶段、审批中的阶段，以及预设固定必选项的保护保持原样。

## 验证

- 修复前，POC 和 Express 的可选 ALWAYS 阶段勾选后变成锁定，两条回归均失败。
- 修复后，全部可选 ALWAYS 阶段均可选中再取消，取消后精确计数恢复至基线。
- 新增消费者仍锁住其必需生产者；缺少必需输入的计划仍不可创建。
- 向导组件对 reverse-engineering 与可选 ALWAYS 阶段连续两轮勾选／取消通过；未调用创建或发送接口。
- 本机实际预览接口 7 组请求通过，包含 intent-capture、units-generation 与 reverse-engineering 的切换。
- 更新发生在执行租约为空时，当前 `260911-test` 的 21 个工作流文件校验值保持不变。
- 全量 **2720 项后端、388 项前端测试通过**，本机安装文件与工作区源码逐字节一致。

这次修复针对提交前的 Plan 预览，没有回改用户已经启动的流程。
