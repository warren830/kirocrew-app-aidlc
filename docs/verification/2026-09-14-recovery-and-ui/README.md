# 会话恢复与交互缺陷修复

## 人工回合丢失的根因

缺陷单第 30 项发生在 KiroCrew 的会话预热恢复路径。
界面中的会话 agent 为 `aidlc`，该 agent 的配置位于项目自己的
`.kiro/agents/aidlc.json`。宿主的 `_eager_spawn` 调用
`resolve_agent_bindings` 时遗漏项目目录，解析结果回退至默认的 `kirocrew`。
随后发送的用户消息复用了这个已预热的会话，因此没有执行 AI-DLC 的
`userPromptSubmit` Hook。

本机日志与工作流记录相互印证：

- 2026-09-13 15:27（Asia/Shanghai），宿主使用 `agent=kirocrew` 恢复目标会话。
- 15:28 的用户回复已出现在宿主会话中。
- AI-DLC 的人工回合计数仍为 8，人工回合标记没有更新，引擎拒绝记录答案。
- 已安装的 agent 配置、适配 Hook、人工回合 Hook 和引擎库均与项目内置资源一致。

修复要求预热路径使用与实际会话工作目录一致的 `project_dir` 解析 agent，
并覆盖首次解析、重新扫描后的解析及应用 agent 恢复分支。
验证使用临时项目中的真实 agent 配置和真实解析器；不向用户会话发送测试消息。

## Studio 修复范围

| 范围 | 原问题 | 修改后的行为 |
|---|---|---|
| 详情页 | 旧详情缓存覆盖更新后的队列记录 | 按操作身份及版本选择记录 |
| 详情页导航 | 旧操作的错误、迟到响应出现在新操作上 | 按操作 ID 隔离展示，保留在途投递保护 |
| 创建向导 | 空间读取失败时没有可操作的反馈 | 显示错误及重试入口 |
| 创建向导 | 创建请求期间仍能切换步骤和修改输入 | 请求结束前锁定步骤导航 |
| 计划建议 | 修改设置后仍能应用旧预览 | 仅允许应用与当前请求一致的预览 |
| 恢复页 | 历史记录缺少 `markers` 时崩溃 | 显示数据不可用 |
| 安装恢复 | 请求进行中仍可取消或刷新，丢失事务展示 | 等待返回事务后切换至事务视图 |
| 安装器 | 提交后中断或删除失败留下 staging，无法再次清理 | 启动恢复重试清理并补齐完成时间 |
| 恢复证据 | 相同证据每次扫描都会递增版本 | 证据不变时不写入，实际变化仍经 CAS 更新 |
| 投递恢复 | 已确认送达的消息仍提供重发及未送达入口 | 仅保留重新核对入口，服务端投递保护保持生效 |
| 恢复提示 | 消息已送达仍显示“无法确定是否送达” | 明确区分会话收到消息与工作流接受答案 |
| 开发脚本 | 写死的旧 Node 安装路径不存在时无法检查和构建 | 默认读取当前 Node 路径，仍支持显式 `NODE_BIN` 覆盖 |

安装清理还覆盖多事务隔离：某个已提交事务无法清理时，先处理其他被中断的事务，
最后报告清理失败，避免一个仓库的文件权限问题阻断所有仓库的恢复。

## 宿主补丁与复验

- `kirocrew-project-agent-prefetch.patch`：KiroCrew 源码、会话规范和回归测试补丁。
- `kirocrew-insider-runtime.patch`：当前安装版本的四处精确修改。
- `verify_host_prefetch.py`：针对指定 KiroCrew 包运行真实解析器测试，隔离数据目录并核对模块来源。

源码工作区的完整预热测试模块通过 69 项，跳过 4 项该旧版本不存在的应用恢复分支。
当前安装版本覆盖全部 14 项专项回归，包括冷缓存、首次预热、恢复预热、
别名优先级、无关工作目录以及应用 agent 恢复分支。
原安装版本有 8 项失败；修改后的安装文件通过全部 14 项。

源码补丁中的测试应用到 KiroCrew 工作区后，可对安装版本执行：

```bash
python verify_host_prefetch.py \
  --package-root /path/to/kirocrew/site-packages \
  --tests /path/to/KiroCrew/test/test_eager_spawn.py
```

本机宿主文件修复独立于 Studio 应用更新。升级或重新安装 KiroCrew 后，
需确认上游已包含该修复，或重新执行上述回归检查。
