### 2.1 `intents.json` schema (`IntentRegistryEntry`, lib.ts 1653)

```ts
export interface IntentRegistryEntry {
  uuid: string;        // UUIDv7 (uuidv7() at 1477: 48-bit ms timestamp + '7' + v4 tail)
  slug: string;        // slugify(label, 24) — lowercase kebab, leading letter forced ("intent-" prefix), fallback "intent"
  dirName?: string;    // on-disk record dir, stored verbatim at birth; OPTIONAL for back-compat (pre-spike rows omit it)
  scope?: string;      // e.g. "poc", "feature", or a custom scope name
  repos?: string[];    // only when non-empty (multi-repo); absent = single-repo default
  status: string;      // "in-flight" at birth; "complete" on WORKFLOW_COMPLETED (updateIntentStatus, 2151); "unknown" for on-disk orphans in listIntents()
}
```

File is a JSON array, pretty-printed with 2 spaces + trailing newline (`writeFileAtomic(path, JSON.stringify(list, null, 2)+"\n")`). Absent/malformed → readers treat as `[]`. Join rule `recordDirMatches(entry, dirName)` (1672): exact `entry.dirName` match, else legacy `<slug>-<id8>` (slug prefix + trailing hex that is a suffix of the uuid).

Real example (DevDelta, 2.6.2):
```json
[
  {
    "uuid": "01a00133-9901-7fdf-815d-5ae4e6e4be02",
    "slug": "review-major-remediation",
    "dirName": "260814-review-major-remediation",
    "scope": "review-major-remediation",
    "status": "in-flight"
  },
  {
    "uuid": "01a047b1-c605-7f76-927a-8193f101d918",
    "slug": "kiro-impact-poc",
    "dirName": "260828-kiro-impact-poc",
    "scope": "poc",
    "status": "complete"
  }
]
```
Note the second row's `scope` stayed `poc` although the state file's Scope was later changed to `feature` (`SCOPE_CHANGED` audit row) — registry `scope` is birth-time only. `status` values observed: `in-flight`, `complete`. The registry `status` is NOT flipped to complete for a completed-then-re-scoped intent that resumes; treat as advisory.

### 2.2 Intent directory naming

`intentDirNameBase(label)` (1544) = `${dateStamp()}-${slugify(label, 24)}` where `dateStamp` = UTC `YYMMDD`. Collisions append `-2`, `-3`, … (`resolveUniqueIntentDir`, 1560, bounded at 1000). Regex for display: `displaySlugFromDirName` strips `^\d{6}-`; legacy `<slug>-<hex>` strips trailing `-[0-9a-f]+`. Reserved names rejected: `RESERVED_RECORD_NAMES` (698) — includes `archive`, etc. **Studio must never derive `dirName` from slug+uuid; always read `dirName` from the row or scan directories for `aidlc-state.md`.**

`createIntent()` (2098) writes a header-only stub `# AI-DLC State Tracking\n` into `<record>/aidlc-state.md` BEFORE the registry row and cursor are written; the full state body is written afterwards by `handleIntentCreateStateBuild` (`aidlc-utility.ts:4029`). A parser can therefore briefly see a one-line state file.

### 2.3 Cursors

- `aidlc/active-space` — one line, space name + `\n`. `ensureActiveSpaceCursor` (1811) uses a staged temp file `aidlc/.aidlc-active-space-<pid>-<uuid>.tmp` + `linkSync` (no-replace) so a concurrent switch wins.
- `aidlc/spaces/<sp>/intents/active-intent` — one line, `dirName` + `\n`. Written by `setActiveIntentCursor` (1834) at birth and on `intent <slug>` switch. Ignored by `activeIntent()` if the named dir lacks `aidlc-state.md`.
- Both are gitignored per-user files. **PRD P-05 basis**: `activeIntent()` is repo-shared (one cursor file per space), not per-session; the per-session map `aidlc/.aidlc-sessions/<session-id>` (content: intent UUID) only drives the resume "rebind offer" and `SESSION_ENDED` attribution.

Parsers in `aidlc-lib.ts`:
- `getField(content, field)` (4562): regex ``^- \*\*<field>\*\*:[ \t]*(.*)$`` with `m` flag; returns trimmed value or null. Empty value returns `""`. **Fields are matched by label only, not by section** — e.g. `Status` is unique because Phase rows are `**Initialization**` etc.
- `parseCheckboxes(content)` (4753): regex `/^- \[([ xSR?-])\] (\S+)\s*—\s*(.*)$/gm` → `{slug, state, suffix}`. The separator is the em dash `—` (U+2014). Suffix is `EXECUTE` or `SKIP: <reason>` or `SKIP` (`setStageSuffix` regex `(EXECUTE|SKIP)\b`). Marker map (`CHECKBOX_MAP`, 112): `[ ]` pending, `[-]` in-progress, `[?]` awaiting-approval, `[R]` revising, `[x]` completed, `[S]` skipped. **Only lowercase `x` and uppercase `S`/`R` are written.** The prototype's `[ \-xXsSrR?]` tolerance is safe but broader than the writer.
- `setOrInsertField(content, "## Runtime State", field, value)` inserts optional rows under `## Runtime State`. Observed optional rows: `Skeleton Stance` (values seen: `scope-dependent`; `handleSetSkeletonStance`), `Construction Iteration` (`unit-major` | `stage-major`, state.ts:744; only `unit-major` is load-bearing), `Parked` (ISO timestamp) + `Parked At Stage` (slug) written by `park`, removed by `unpark`; `Active Unit`, `Unit State`, `Unit Pause Reason`, `Unit Next Action` (unit lifecycle receipts, state.ts:1043–1052); `Merge-Held` (aidlc-bolt, per-Bolt forked state). DevDelta's real file has `- **Skeleton Stance**: scope-dependent` inserted AFTER a blank line and BEFORE `## Phase Progress` with no separating blank line — parsers must not assume a blank line before `##`.
- `Construction Autonomy Mode` (`AUTONOMY_MODE_FIELD`, 4582) — `isAutonomousMode()` is true only for the literal `autonomous`. DevDelta's file lacks this row entirely; `setFieldStrict` would throw if `set-autonomy` were called.
- `Completed` counter is resynced to the actual `[x]` count by `checkbox`/`advance`/`finalize`. `Total Stages` counts EXECUTE stages (in DevDelta: 33 after scope change to `feature`, 8 `[x]`).
- `Stages to Execute` / `Stages to Skip` use stage NUMBERS (`0.1 … 4.7`), not slugs; `Stages to Skip` carries free-text reasons in parentheses.
- `State Version`: `classifyStateVersion()` (8010–8090) regex `/^- \*\*State Version\*\*:[ \t]*(\S+)[ \t]*$/m`; must be a bare integer; `CURRENT_STATE_VERSION = "8"` (2.6.2) / `7` (2.2.10 template). `past`/`future`/`unparseable` all make `next`/`report`/`--doctor` REFUSE (error directive). v8 = "renamed `application-design`→`domain-design`, inserted `contract-design`". v7 files (devlake) are therefore un-advanceable on a 2.6.2 install — a Studio "incompatible state" condition.
- Real devlake 2.1.1 file has an extra blank line after `## Runtime State` and `Phase Progress` says `Initialization: Active` while `Current Status` is elsewhere — the "phase_stage_disagreement" the prototype already detects.

## 5. Audit trail

### 5.1 Shard naming and reading

- `auditShardName(projectDir)` (lib.ts 3125): `${host}-${cloneId}.md` where `host = hostname().toLowerCase().replace(/[^a-z0-9-]+/g,"-").replace(/^-+|-+$/g,"").slice(0,48) || "host"`. DevDelta shards: `603e5f4a8072-26e77d17b1cd.md` (hostname is a hex string on this Mac) and, for the other intent, an additional `603e5f4a8072-747664ca2c41.md` (a second clone id, i.e. a re-clone/worktree wrote there).
- `auditShards()` (3147): every `*.md` under `<record>/audit/`, sorted by filename. `readAllAuditShards()` concatenates with `"\n"`. `readAuditShardEvents()` (3194) preserves `{shard, shardIndex, pos, timestamp, event, block}`.
- **Chronological order = sort by `**Timestamp**` (second precision, lexicographic ISO), tie-break by buffer position WITHIN a shard only.** Cross-shard same-second ties are "causally unordered" and authority checks fail closed (`humanActedSinceGate`, 2534). `findAllEvents(audit, event, slug?)` (5425) implements the sort.
- Shard header: `# AI-DLC Audit Log\n` (created by `ensureAuditFile`, audit.ts 253).

### 5.2 Block format (`renderAuditBlock`, audit.ts 394–411)

```
\n## <Heading from EVENT_HEADINGS or the event name>\n
**Timestamp**: <ISO YYYY-MM-DDTHH:MM:SSZ>\n
**Event**: <EVENT_TYPE>\n
**<Field>**: <value with \r\n|\n| |  escaped as literal \n>\n
...\n
\n---\n
```
Blocks are split on `\n---\n` after CRLF→LF normalisation. `auditBlockField(block, name)` (3050): first line starting with `**<name>**:` (tolerates a leading `- `). Field keys must match `/^[A-Za-z][A-Za-z0-9 ._()/-]*$/`; `Event` is reserved. Heading map `EVENT_HEADINGS` (audit.ts 166–252) — e.g. `STAGE_COMPLETED`→`Stage Completion`, `HUMAN_TURN`→`Human Turn`, `WORKFLOW_COMPLETED`→`Workflow Completion`, `PHASE_VERIFIED`→`Phase Verification`, `SCOPE_DETECTED`→`Scope Detection`, `RECOMPOSED`→`Plan Recomposed`, `HEALTH_CHECKED`→`Health Check`. **Parse on `**Event**:`, never on the heading** (headings changed across versions; v2.0 emitted free-form `## Artifact Update` headings).

### 5.4 HUMAN_TURN semantics (lib.ts 2534–2600, `humanActedSinceGate`)

Resolution events = `GATE_APPROVED`, `GATE_REJECTED`, `QUESTION_ANSWERED`, `SUMMARY_CONFIRMATION_RECORDED`, plus `AUTONOMY_MODE_SET` with `Mode: autonomous`. A human is "present" iff the latest `HUMAN_TURN` is strictly later than the latest resolution (timestamp), or equal-second AND in the same shard at a later position than EVERY latest resolution. Empty ledger → fail open (true). No human turn on record → false. On Kiro the ONLY writer is `aidlc-kiro-adapter.ts verb-intercept` (`userPromptSubmit`), gated on `aidlc-state.md` existing. `approve` (state.ts 2409+) also requires `--user-input` non-empty and not matching `NON_ANSWER_RE` (`cancel(led)?|dismiss(ed)?|abort(ed)?|timed out|timeout|no answer|…`). PRD §7 item 4 is confirmed by adapter lines 209–240 (turn counter bump is a SEPARATE try block from the HUMAN_TURN mint).

## 6. Artifacts, questions, reviews, plan approval, traceability, DAG

### 6.1 Where produced artifacts live

- Engine resolves `produces[]` NAMES to `<record>/<phase>/<slug>/<artifactFilename(name)>` (`artifactFilename` lib.ts 3253: `name === "traceability" ? "traceability.json" : name + ".md"`). Per-unit stages (`for_each: unit-of-work` = `functional-design`, `nfr-requirements`, `nfr-design`, `infrastructure-design`, `code-generation`; `KNOWN_PER_UNIT_STAGES` lib.ts 78) resolve to `<record>/construction/<unit>/<slug>/<file>`. `producesArtifactUnit` (3306) extracts `<unit>` as the single path segment after `/construction/`.
- Codekb stage (`KNOWN_CODEKB_STAGES = {"reverse-engineering"}`, lib.ts 3246): 9 artifacts land at `aidlc/spaces/<sp>/codekb/<repo>/<name>.md`; only `memory.md` (and possibly `scan-*.md` scratch, as in DevDelta's `inception/reverse-engineering/scan-backend.md`) appears in the intent dir. `reverse-engineering-timestamp.md` carries a fenced `yaml` `Scope of Analysis` block with `scope_version: 1`, `kind: full|partial`, `intent`, `fingerprint` (`codekbScopeFingerprint`), `analyzed.paths[]`, `analyzed.components[]`, `shallow.paths[]`.
- Unit names: `UNIT_NAME_REGEX = /^[A-Za-z0-9][A-Za-z0-9._-]*$/` (max 64); Bolt slugs `/^[a-z][a-z0-9-]*$/` (max 64); worktree = `.aidlc/worktrees/bolt-<slug>`.
- Real per-unit tree (DevDelta): `construction/kiro-impact-poc/code-generation/{code-generation-plan.md, code-generation-questions.md, code-summary.md, traceability.json, unit-test-instructions.md}`; `construction/build-and-test/{build-and-test-summary.md, build-instructions.md, build-test-results.md, cross-unit-traceability.md, integration-test-instructions.md, memory.md, performance-test-instructions.md, security-test-instructions.md, test-results.md}`. agentbridge (2.2.6): `construction/walking-skeleton/{code-generation,functional-design,nfr-requirements}/...`.

Freshness floor (`freshReviewReceipts`, 3563): `WORKFLOW_STARTED`/`STAGE_JUMPED` (any stage), the stage's `STAGE_STARTED` (unless unit-major) and `GATE_REJECTED`; a later `ARTIFACT_CREATED/UPDATED` on a declared produces path invalidates. `review_class: advisory` ⇒ iteration cap 1 and both verdicts terminal.

### 6.2 Questions files

- Name: `<stage-slug>-questions.md` in the stage dir (per-unit: `construction/<unit>/<slug>/<slug>-questions.md`). Stop-hook scans `readdirSync(stageDir).filter(f => f.endsWith("-questions.md"))`.
- Format (stage-protocol §3): `## Q<n>. <question>` headings; options `A.`–`E.` and mandatory `X. Other (please specify)`; blank tag `[Answer]:` (regex `/^\[Answer\]:[ \t]*(.*)$/m`); an answer of empty or underscores-only = unanswered. Multi-select answers `[Answer]: A, B, E`.

Stages carry `summary_confirmation: required|if-present` in stage-graph.json. **Editing a questions file after confirmation invalidates it — Studio must never write these (PRD FR-Q-005 confirmed).**

## 12. Implications for the Studio read model (concrete)

1. Discover installs by `<repo>/<dir>/tools/data/harness.json` for `dir ∈ {.kiro,.claude,.codex,.aidlc,.cursor}` and read `AIDLC_VERSION` from `<dir>/tools/aidlc-version.ts` via regex; a repo may carry several installs at different versions (devlake: `.kiro` 2.1.1, `.claude` 2.2.7). Studio's "installed version" must be per-engine-dir.
2. Read `aidlc/active-space` (default `default`), then `aidlc/spaces/<sp>/intents/intents.json` (tolerate missing/malformed), then scan `intents/*/aidlc-state.md`; join rows by `dirName` (fallback legacy suffix rule). Surface registry-less dirs as orphans (`status: "unknown"`), exactly as `listIntents()` does.
3. Parse `aidlc-state.md` with the two regexes in §3.1; take `Current Stage`, `Status`, `Lifecycle Phase`, `Construction Autonomy Mode`, `Parked`, `Active Unit/Unit State`, and the checkbox grid. `[?]` = "Waiting for you" (gate); `[R]` = revising; `Parked` row ⇒ PRD `Parked`; `Status: Completed` ⇒ Completed. Compare `State Version` to the installed `CURRENT_STATE_VERSION` (grep `export const CURRENT_STATE_VERSION = "N"` in `<dir>/tools/aidlc-lib.ts`) for the incompatibility finding.
4. Validate `.aidlc-active-directive.json` exactly as `readActiveDirectiveMarker` does (version 1, slug regex, 64-hex digest equal to sha256 of the whole state file) — a mismatch is "stale directive", not corruption.
5. Read audit shards by globbing `audit/*.md`, splitting on `\n---\n`, keying on `**Event**:`, merge-sorting by `**Timestamp**` then per-shard position; never assume a single shard; tolerate unknown events; keep raw blocks for the Evidence drawer. Pending human question = `DECISION_RECORDED` for the current stage not followed by `QUESTION_ANSWERED` (`hasPendingDecision`), or a `<slug>-questions.md` with a blank `[Answer]:`; human presence = `humanActedSinceGate` rule in §5.4.
6. Redact `.aidlc-steering-token-key` and `usage-ledger.json` transcript paths in any export; never write `*-questions.md`, `aidlc-state.md`, audit shards, or cursor files.
7. For the Workflow Map, load the repo's own `stage-graph.json` (per install) and `scope-grid.json`; show `review_class`, `reviewer`, `for_each`, `mode`, `summary_confirmation`, `produces/consumes`; take depth/test-strategy/review_cap from `scopes/*.md` frontmatter, including project-added scopes.
